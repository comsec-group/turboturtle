# Turboturtle

HLS compiler fuzzer that generates random constant-time C programs and random HLS compiler configurations.

## Dependencies

- docker
- python3.12
- For Dynamatic's smart buffer placement: Gurobi (free academic licenses can be obtain from the website, see [Dynamatic advanced installation instructions](https://epfl-lap.github.io/dynamatic/UserGuide/AdvancedBuild.html#1-gurobi))
- For Dynamatic's mapbuf buffer placement: Yosys and abc (can be the version within Yosys) are required in case BLIF files are missing (which can happen with some generated programs). See [Dyanamatic documentation](https://epfl-lap.github.io/dynamatic/DeveloperGuide/DynamaticFeaturesAndOptimizations/Buffering/MapBuf/BlifGenerator.html). Most Yosys versions should work. Tested with Yosys commit 6f9c515a222b322d8d3605e09eb69e7023e61e70.

- Optionally: Questa simulator, installed on a server reachable via ssh. Configure the server user and name in config.toml:eda_server_remote. It is only required for designs that contain VHDL output, which is generated by some HLS tool configurations. Our default simulator is Verilator, installed in the docker container.

## Installation

- `cd toolchain/dockerfiles`
- `./build.sh`
    - builds the Verilator and Bambu docker container
    - maybe needs additional --network host argument if error
- `cd ../..`
- `python3 -m venv .venv`
- `source .venv/bin/activate`
- `pip install -r requirements.txt`

### Installation of Dynamatic


Optional: Install Gurobi (see [Dynamatic advanced installation instructions](https://epfl-lap.github.io/dynamatic/UserGuide/AdvancedBuild.html#1-gurobi)).
Without Gurobi, Dynamatic's mapbuf buffer placement algorithm cannot be used. In that case, remove the option from the set of possible arguments in [pipeline.py](./turboturtle/pipeline/pipeline.py), class DynamaticPipeline, function: _synth. Comment this line: `"--buffer-algorithm mapbuf"`.
Or install the CBC solver (see Dynamatic installation instructions).

Make sure that gurobi_cl can be called (you have to set Gurobi environment variables).

Then, follow Dynamatic's installation instructions: https://epfl-lap.github.io/dynamatic/GettingStarted/InstallDynamatic.html
Update the path to the Dynamatic installation (dynamatic_path) in config.toml.

#### Installation of Yosys

Build [Yosys](https://github.com/yosyshq/yosys) (and abc, which is cloned if you clone recursively) and set up your path:

export PATH=your/path/yosys/:${PATH}
export PATH=your/path/yosys/abc:${PATH}


## Preparation

- copy `config_template.toml` to `config.toml` and change where necessary (vscode has toml language support extensions).
- change `<user>@remote-address`
- change remote working directory (`username@remote-address:/path/to/working/directory`)
- make sure the directory exists on the remote
- specify the path to Dynamatic's _directory_ in the `dynamatic_path` variable
    - TurboTurtle will invoke Dynamatic with `<dynamatic_path>/bin/dynamatic`
    - Currently this needs to be an absolute path (see Dynamatic [issue](https://github.com/EPFL-LAP/dynamatic/issues/981) )


## Usage

Always activate the Python environment first: `source .venv/bin/activate`

- `python start.py` reads the `config.toml` and starts a fuzzing run based on the configuration
    - the output will be located in `<working_dir>` if `cleanup` is false
    - if `backup` is true, all output is copied to the `<backup_dir>`
- `python start.py --custom-program <program.c> <design_name> <additional HSL args> ...`
    - supply a custom C input program.
    - currently only supported for Bambu HLS.
    - top-function name has to be specified in `config.toml`

### Custom C input program

Supply a custom C input program.
Currently only supported for Bambu HLS.
Top-function name is specified in `config.toml`.

- `python start.py --custom-program-bambu <program.c> <design_name> <additional HSL args> ...`

The result will be in cat <working_dir>/<design_name>/report.json.
On error, you find logs in <working_dir>/<design_name>/logs.

### Testing the flow
First, activate the Python environment `source .venv/bin/activate`.
Run `python start.py` with the `config.toml` adapted with your file paths. Most likely the generated programs with this default configuration cannot be synthesized.

Expected output: CTurtle generates a program. Dynamatic and Bamub launch and try to synthesize the program, but the synthesis will most likely fail because of a non-supported configuration.

### Test Bambu

`python3 start.py --config config_bambu.toml`

Expected result: A program should be generated by CTurtle. This program should be synthesized. In some cases this might fail due to a non-supported random HLS configuration. In that case, retry a few times. The RTL code should be automatically verified via simulation. Most likely you will not find a timing side channel in the design, because the config file contains all our discovered HLS rules for Bambu. If you do find a timing side channel, you might have discovered a new vulnerability. ## Documentation

Some useful notes about the project.


### CTurtle generation process

- by creating an instance of the `Program` class (`turboturtle/cturtle/program.py`), a random C program is generated
- the `generate_top_function` method generates the content of the top function body
    - generates k declarations by invoking the `produce_k_declarations` method
    - generates k statements by invoking the `produce_k_statements` method
        - calls the `produce_statement` method k times
        - the main logic for how random statements are produced is in the `produce_expression_core` method
        - a random statement can be any of the statements from the configuration file
        - depending on the statement, other random statements (in the case of the compound statement) or random expressions are generated
        - the `ExpressionStatement` always contains an `AssignmentExpression` to increase the chance to generate complex data flows
        - the logic for how random expressions are generated is located in the `produce_expression_core` method
        - a random expression can be any of the expressions from the configuration file

### Reduction

- currently HLS arg reduction only works for Bambu
- the other HLS compilers have not been tested

### CT rules

- specifing rules for C programs generation through the configuration is currently limited to:
    - secret-dependent control flow
    - secret-dependent memory accesses
    - HLS arg combination to avoid for Bambu
- the system for more complex rules is in place but currently needs to be extended directly in the code
    - `turboturtle/cturtle/expression_factory.py --> produce_expression_core` contains logic for how expressions are generated
        - additional rules can be added by applying more filter rules
        - there is a comment in the code for a division expression using only integer data types
    - `turboturtle/cturtle/statement_factory.py --> produce_statement_core` contains logic for how statements are generated
    - Dynamatic argument combinations can be limited [here](./turboturtle/pipeline/pipeline.py), class DynamaticPipeline, method _synth.


### Random data
Random data values are generated in prepare_sim_data() in [turboturtle/pipeline/pipeline.py](turboturtle/pipeline/pipeline.py).
They are read and stored into a <portname>.mem file for each simulation iteration in [/templates/remote_sim.py](/templates/remote_sim.py).
After the run, the simulation directory will contain the random values of the latest simulated data. In case a timing side channel was detected, the files will show the inputs that surfaced it.
We invoke each synthesized algorithm 25000 times, with new random data in each invocation.

## Troubleshooting

### Problems with locale on the EDA server

/bin/sh: warning: setlocale: LC_ALL: cannot change locale (C.UTF-8)

put `unset LC_ALL` into your .bashrc on the server that connects to the EDA server


### Missing configuration entry

Errors like the following mean that you are missing a configuration option (e.g., design_types) in config.toml.
  File "hls-fuzzer/turboturtle/config.py", line 25, in load
    self.design_types = config_dict["design_types"]
                        ~~~~~~~~~~~^^^^^^^^^^^^^^^^
KeyError: 'design_types'

### CBC not installed


Exception for task _start_pipelineLLVM ERROR: CBC not installed!

If you see this error in the Dynamatic output, e.g., in `turboturtle/fuzzing/run_20260618224453/run_20260618224453_design_0004/logs/error.txt`, either install CBC (if you cannot use Gurobi) or make sure your Gurobi installation is set up correctly (installed, license installed, environment variables set according to Dynamatic and Gurobi installation instructions).

Maybe you built Dynamatic in a terminal where Gurobi environment variables were not set? Delete dynamatic/build and re-build it.

### Missing BLIF files

`The buffer placement algorithm MapBuf expects the BLIF file at location: ...`

TurboTurtle tries to automatically invoke the calls to generate missing BLIF files for Dynamatic. This requires Yosys to be installed and on the path.
